# 2장 보강 — writer 공통 지시

2장(Applications and Integration)에 CCAR-P D3 · CCAR-F D4(2장 배정분) 문항을 반영한다. 50문항을 시험 도메인별로 2명에게 나눴고, 너는 그중 한 묶음(`w{N}.json`)을 맡는다.

## 먼저 읽을 것
1. `.claude/rules/knowbook-style.md` (R1~R12, 처음부터 그대로 따른다)
2. `work/knowbook/orig/2_Applications_and_Integration.md` (기존 2장. 수정 금지, 읽기만)
3. 네 입력 파일 `work/knowbook/ch2/w{N}.json` (필드 `topic`은 묶음 안 분류. `tag_note`는 참고용)

## 쓸 것
출력: `work/knowbook/ch2/part{N}.md` 하나. 최종 장 파일은 건드리지 않는다(나중에 merger가 합친다).

형식(블록 헤더를 정확히 이 문자열로 쓴다):

```
@@ ADD-TO: <기존 ### 소제목 전체 문자열 그대로>
(그 소절 표에 덧붙일 행, 또는 새 표. 마지막 줄은 이 블록에서 새로 쓴 id만 담은 <sub>근거: ...</sub>)

@@ NEW-SECTION
### <소제목>   ← 번호를 붙이지 않는다(merge 스크립트가 1.16부터 자동으로 붙임)
**핵심 한 줄**
(표)
<sub>근거: ...</sub>

@@ RULES      (2장 "상황 | 정답" 표에 덧붙일 행만)
@@ TRAPS      (3장 "오답 | 이유" 표에 덧붙일 행만)
@@ MEMO       (4장 "이름 | 의미" 표에 덧붙일 행만)
@@ CHECK      (5장 `- [ ]` 항목, 2~4개)
```
- RULES·TRAPS·MEMO·CHECK 블록도 끝에 `<sub>근거: ...</sub>` 한 줄을 둔다.
- 기존 소절과 주제가 겹치면 ADD-TO로 덧붙인다. 기존 행과 같은 내용은 다시 쓰지 않는다. 겹치지 않으면 NEW-SECTION을 만든다.
- 기존 내용을 고치거나 반박하지 않는다. 문항 해설이 기존 내용·공식 문서와 어긋나 보이면 그 행에 `⚠️` + 이유 한 줄을 남긴다.
- 그림 줄(`![...]`)은 쓰지 않는다. 그림은 다른 subagent가 넣는다.

## 근거 규칙
- 근거 id는 입력 JSON의 `id`를 줄이지 않고 그대로 쓴다(예: `CCAR-F-Udemy03-0033`).
- id는 `<sub>근거: ...</sub>` 줄에만 쓴다. 본문·표 안에 쓰지 않는다.
- 입력 문항은 모두 한 번 이상 인용한다. 끝나면 입력 id가 part 파일에 전부 있는지 Bash(python3)로 직접 대조한다.
- 문항 정답·해설에 근거한 지식만 쓴다. 문제를 옮겨 적지 말고, 처음 보는 문제에도 쓸 수 있게 일반화한다.
- 다른 topic에 더 맞아 보이는 문항도 버리지 말고 네 파일 안 가장 가까운 소절에 넣는다.

## 보고
NEW-SECTION 소제목 목록, ADD-TO 대상 소제목, 인용 id 수/입력 id 수, ⚠️ 개수만 짧게.

## 추가 주의
- ADD-TO 헤더는 `### ` 와 번호를 포함한 기존 줄 전체를 그대로 쓴다(예: `@@ ADD-TO: ### 1.8 구조화 출력 (Structured outputs)`).
- tool 설계는 8장, prompt·schema 설계 원칙은 6장, 모델 선택은 5장 몫이다. 문항이 그쪽이면 API 통합·구현 관점으로 일반화한다. 입력 파일의 topic 필드는 시험 도메인 이름이다.
