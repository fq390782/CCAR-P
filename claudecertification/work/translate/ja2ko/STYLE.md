# 일본어 → 한국어 번역 스타일 가이드 (Udemy 일본어 문항의 문제·보기)

## 목표
한국어 모어 화자가 일본어를 보지 않고도 **한 번 읽고 이해**할 수 있어야 한다. 일본어 문장을 단어 단위로 옮기는 직역(번역투)을 피하고, 의미를 파악한 뒤 자연스러운 한국어로 쓴다.

## 입력
- `question`, `choices`: 일본어 원문. **번역의 기준이다.**
- `en_question`, `en_choices`: 같은 문항을 영어로 옮긴 참고본(기계 번역). 일본어의 뜻이 애매하거나 기술 용어의 원래 영어 표기를 확인할 때만 참고한다. 둘이 어긋나면 일본어를 따른다.

## 문장
1. 문제 본문과 보기는 **합니다체**로 쓴다(질문은 "~입니까?", "~무엇입니까?"). 같은 문항의 해설이 이미 합니다체 한국어로 되어 있어 맞춘다.
2. 일본어식 표현을 푼다: "~において" → "~에서", "~に対して" → 문맥에 맞게, "~を行う" → 구체적 동사, "~ことができる" 남발 → 간결하게, "~という" 반복 → 줄인다. 한자어를 그대로 음독하지 않는다(例: 運用 → "운용"보다 문맥상 "운영", 想定 → "예상/가정").
3. 주어·조사를 한국어답게 쓴다. 긴 문장은 나눠도 된다.
4. 보기는 같은 문항 안에서 어미를 통일한다(대부분 "~한다" 대신 합니다체 "~합니다"나 원문이 명사형이면 명사형).
5. **줄바꿈 구조 유지**: 문단 구분(빈 줄 `\n\n`)의 개수와 위치를 일본어 원문과 똑같이 맞춘다. 줄 단위 목록(한 줄에 항목 하나)도 줄 수를 그대로 둔다. 문제은행이 문단끼리 짝지어 보여 주기 때문이다.

## 용어
- 기술 용어는 영어 원문 표기로 쓴다: hook, PreToolUse, subagent, agent, skill, CLAUDE.md, system prompt, prompt, context, context window, MCP, MCP server, turn, loop, fork, orchestration, escalation, few-shot, JSON schema, tool_use 등. 일본어가 카타카나(コンテキスト, スキル, フック, サブエージェント)여도 영어로 쓴다. 영어 표기는 en 참고본에서 확인한다. 조사는 자연스럽게(hook이 / subagent를).
- 일반 명사 "도구(ツール)"는 "도구"로 쓰고, 식별자(`query_plant_telemetry`, Read, Bash, Grep 등)는 그대로 둔다.
- 일반 어휘는 한국어로. 억지 번역어를 만들지 않는다.
- 코드, 백틱, 파일명, 경로, 옵션, 숫자·단위·금액은 그대로.

## 충실성
- 의미를 더하거나 빼지 않는다. 보기 사이의 미묘한 차이(정답을 가르는 단서)를 반드시 살린다.
- 원문이 이상해 보여도 고치지 않는다. 의심 사항은 `notes`에 적는다.

## 출력 형식
입력과 같은 길이·순서의 JSON 배열: `[{"id","question","choices":{"A":..},"notes"(선택)}]`. 보기 키는 입력과 동일. en_* 필드는 출력하지 않는다.
