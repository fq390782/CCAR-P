<h3 id="bank-mocks-h94">M2-Q23 (V2-D3.2)</h3>

<p id="sec-bank-mocks-p419" data-kind="prose"><strong>Scenario.</strong> An agent calls a vendor API with a shared API key. Three
teams share the key. An incident needs attribution: which team made the
call.</p>

<p id="sec-bank-mocks-p420" data-kind="prose"><strong>Question.</strong> What is the correct design?</p>

<p id="sec-bank-mocks-p421" data-kind="prose"><strong>Options.</strong>
A) Keep the shared key. Attribution does not matter.
B) Per-team credentials (or per-team tokens), so each call carries its
caller&#x27;s identity. No shared credentials when attribution matters.
C) A bigger model.</p>

<p id="sec-bank-mocks-p422" data-kind="prose">D) Delete the logs.</p>

<p id="sec-bank-mocks-p423" data-kind="prose"><strong>Key.</strong> B. Decisive phrase: "needs attribution: which team made the
call." Why: V2-D3.2 forbids shared credentials when attribution
matters. Per-team credentials make each call attributable.
Counterfactual: A wins for a read-only internal dashboard with no
attribution need.</p>


<h3 id="bank-mocks-h95">M2-Q24 (V2-D3.3)</h3>

<p id="sec-bank-mocks-p424" data-kind="prose"><strong>Scenario.</strong> A document pipeline measures p95: OCR 2.5 s, chunking 0.2
s, embedding 0.8 s, model 1.0 s. Total 4.5 s. The SLA is 3.0 s.</p>

<p id="sec-bank-mocks-p425" data-kind="prose"><strong>Question.</strong> Which stage must you optimize first?</p>

<p id="sec-bank-mocks-p426" data-kind="prose"><strong>Options.</strong>
A) Chunking.
B) OCR: it holds over half the total.
C) Embedding.
D) Add a spell-check stage.</p>

<p id="sec-bank-mocks-p427" data-kind="prose"><strong>Key.</strong> B. Decisive phrase: &quot;OCR 2.5 s... Total 4.5 s. The SLA is 3.0
s.&quot; Why: OCR is 56% of the budget. The 1.5 s cut must come mostly from
it.</p>

<p id="sec-bank-mocks-p428" data-kind="prose">A saves 0.2 s at best. Counterfactual: C wins when embedding
dominates.</p>


<h3 id="bank-mocks-h96">M2-Q25 (V2-D3.4)</h3>

<p id="sec-bank-mocks-p429" data-kind="prose"><strong>Scenario.</strong> A booking agent spans a web service, a queue, and a worker.
A booking vanishes. Each hop logs, but the queue drops the correlation
id.</p>

<p id="sec-bank-mocks-p430" data-kind="prose"><strong>Question.</strong> What is the fix?</p>

<p id="sec-bank-mocks-p431" data-kind="prose"><strong>Options.</strong>
A) More logs in the web service.
B) Propagate the run id through the queue: the queue must accept and
forward it, so the run reconstructs end to end.
C) A bigger model.
D) A second queue.</p>

<p id="sec-bank-mocks-p432" data-kind="prose"><strong>Key.</strong> B. Decisive phrase: "the queue drops the correlation id."
Why: the queue is the broken link in trace propagation. Every hop must
forward the id. Counterfactual: A wins when the web service logs
nothing.</p>

<p id="sec-bank-mocks-p435" data-kind="prose"><strong>Options.</strong>

B) Citation checks: verify cited spans support the claims.

definitional.</p>


<h3 id="bank-mocks-h98">M2-Q27 (V2-D3.5)</h3>

<p id="sec-bank-mocks-p439" data-kind="prose"><strong>Question.</strong> What is the fix?</p>

<p id="sec-bank-mocks-p440" data-kind="prose"><strong>Options.</strong>
A) Bigger fixed chunks.
B) Structure-aware chunking: split by manual section so each chunk is a
complete unit, with overlap or metadata at boundaries.
C) More documents.
D) A stronger model.</p>

<p id="sec-bank-mocks-p441" data-kind="prose"><strong>Key.</strong> B. Decisive phrase: "miss content that spans chunk
boundaries." Why: fixed cuts split meaning. Structure-aware chunks keep
units whole. A makes bigger broken pieces. Counterfactual: A wins when
chunks are simply too small for the query unit.</p>


<h3 id="bank-mocks-h99">M2-Q28 (V2-D3.6)</h3>

<p id="sec-bank-mocks-p442" data-kind="prose"><strong>Scenario.</strong> A flight-status bot answers "where is my flight." Flight
positions update every 30 seconds. The design caches positions for one
hour.</p>

<p id="sec-bank-mocks-p443" data-kind="prose"><strong>Question.</strong> What is wrong?</p>

<p id="sec-bank-mocks-p444" data-kind="prose"><strong>Options.</strong>
A) Nothing. Caching is good.
B) Live state behind a stale cache: positions change every 30 seconds,
so an hour-old position is wrong. Put live positions behind a tool
call.
C) The bot needs a bigger model.</p>

<p id="sec-bank-mocks-p445" data-kind="prose">D) Flights should stop moving.</p>

<p id="sec-bank-mocks-p446" data-kind="prose"><strong>Key.</strong> B. Decisive phrase: "update every 30 seconds... caches
positions for one hour." Why: V2-D3.6 puts live transactional state
behind a tool call. An hour-old position during operations is a wrong
answer served fast. Counterfactual: A wins for slow-changing data like
airport addresses.</p>

buys nothing without reuse. Counterfactual: A wins when four more

<h3 id="bank-mocks-h102">M2-Q31 (V2-D3.8)</h3>

<p id="sec-bank-mocks-p458" data-kind="prose"><strong>Scenario.</strong> A chat agent uses 6 tools. The SLA is 800 ms. Token budget
is comfortable.</p>

<p id="sec-bank-mocks-p459" data-kind="prose"><strong>Question.</strong> Which context strategy fits?</p>

<p id="sec-bank-mocks-p460" data-kind="prose"><strong>Options.</strong>
A) Progressive discovery.
B) Monolithic context: load all 6 schemas up front. No discovery round
trips under the tight SLA.
C) Remove the tools.
D) Discovery with three round trips.</p>

<p id="sec-bank-mocks-p461" data-kind="prose"><strong>Key.</strong> B. Decisive phrase: "6 tools... SLA is 800 ms." Why: tiny

threaten 800 ms for no token gain. Counterfactual: A wins at 60 tools
with a loose SLA.</p>


<h3 id="bank-mocks-h103">M2-Q32 (V2-D4.1)</h3>

<p id="sec-bank-mocks-p462" data-kind="prose"><strong>Scenario.</strong> A code-review bot must catch security bugs. The team
debates metrics.</p>

<p id="sec-bank-mocks-p463" data-kind="prose"><strong>Question.</strong> Which metric is primary?</p>

<p id="sec-bank-mocks-p464" data-kind="prose"><strong>Options.</strong>
A) Lines reviewed per minute.
B) Recall on known vulnerability classes: the share of real bugs
caught.
C) Token cost.
D) Uptime.</p>

<p id="sec-bank-mocks-p465" data-kind="prose"><strong>Key.</strong> B. Decisive phrase: "must catch security bugs." Why: the
objective is to catch bugs. Recall on the bug classes measures exactly
that. A measures speed, C cost, D availability. Counterfactual: C wins
when the budget binds and recall is already met.</p>
