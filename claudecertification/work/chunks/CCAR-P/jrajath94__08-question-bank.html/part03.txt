<ol class="qb-opts" type="A"><li>Clear AI disclosure at conversation start, citations linking each factual claim to its source document, and a visible appeal path (human review request) for disputed answers.</li>
<li>Publishing the system prompt so users can see how it works.</li>
<li>A disclaimer that the assistant "may make mistakes" with no other changes.</li>
<li>A small "AI assistant" label in the footer of the page.</li>
</ol>
<details class="pq"><summary>Show answer and explanation</summary>
<div class="pq-answer"><span class="qb-verdict">Answer: A</span><p class="qb-why" id="question-bank-106-items-in-number-order-p54" data-kind="prose"><strong>Why A is correct:</strong> Each constraint maps to one element. Upfront disclosure tells users it is AI. Per-claim citations let them verify. The appeal path gives recourse. All three together make transparency operational rather than decorative.</p>
<ol class="qb-distractors" type="A"><li>D is wrong. A footer label is easy to miss. It provides no verifiability or recourse.</li>
<li>B is wrong. Publishing the prompt exposes internals. It does not help users verify any specific answer.</li>
<li>C is wrong. A generic disclaimer shifts blame to the user. It provides no verification or appeal.</li>
</ol>
